🧪 CPU Scheduling — Lab Procedure

This lab covers all major CPU scheduling algorithms used in Operating Systems. Follow the procedure below to understand theory, implementation, and analysis of each algorithm.

🎯 Aim

To study, understand, and implement the following CPU Scheduling algorithms and analyze their performance using metrics like Turnaround Time (TAT), Waiting Time (WT), Response Time (RT), and CPU Utilization.

  • First Come First Served (FCFS)
  • Shortest Job First (SJF) — Non-Preemptive
  • Shortest Remaining Time First (SRTF) — Preemptive SJF
  • Round Robin (RR) with configurable Time Quantum
  • Priority Scheduling (Non-Preemptive)
  • Multi-Level Feedback Queue (MLFQ)

📚 Background Theory

CPU Scheduling is the process by which the operating system decides which process from the ready queue gets to run on the CPU. It is essential for:

  • Maximizing CPU Utilization — keeping the CPU as busy as possible
  • Maximizing Throughput — number of processes completed per unit time
  • Minimizing Turnaround Time — time from submission to completion
  • Minimizing Waiting Time — total time spent in the ready queue
  • Minimizing Response Time — time until the first response is produced

📐 Key Formulae

Completion Time (CT) = Time when process finishes execution
Turnaround Time (TAT) = CT − Arrival Time (AT)
Waiting Time (WT) = TAT − Burst Time (BT)
Response Time (RT) = First CPU allocation time − AT
Average TAT = Σ TAT / n  |  Average WT = Σ WT / n
CPU Utilization (%) = (Busy Time / Total Time) × 100
Throughput = Number of Processes / Total Time

🔍 Algorithm Overview

🏁
FCFS (First Come First Served): Processes are executed in the order they arrive. Simple but can cause the "Convoy Effect" — short processes wait behind long ones. Non-preemptive.
⚡
SJF (Shortest Job First): The process with the smallest burst time runs next. Optimal for minimizing average waiting time. Can cause starvation for longer processes. Non-preemptive.
🔄
SRTF (Shortest Remaining Time First): Preemptive version of SJF. When a new process arrives with a shorter remaining burst time than the currently running process, it preempts it.
🔁
Round Robin: Each process gets a fixed time quantum (q). After q units, the process is preempted and placed at the end of the ready queue. Fair and prevents starvation. Widely used in time-sharing systems.
🏆
Priority Scheduling: Each process is assigned a priority. The process with the highest priority (lowest number) runs first. Can cause starvation; solved using "aging" — gradually increasing priority of waiting processes.
🏢
MLFQ (Multi-Level Feedback Queue): Uses multiple queues with different priority levels and scheduling algorithms. Processes can move between queues based on their behavior. I/O-bound processes get higher priority; CPU-bound processes move to lower queues.

📝 FCFS Pseudocode

// First Come First Served (FCFS) Scheduling
INPUT: n processes with {PID, Arrival Time (AT), Burst Time (BT)}

STEP 1: Sort processes by Arrival Time (AT) in ascending order
STEP 2: Initialize current_time = 0

FOR each process P in sorted order:
    IF current_time < P.AT:
        current_time = P.AT  // CPU is idle until process arrives
    
    P.CT = current_time + P.BT   // Completion Time
    P.TAT = P.CT - P.AT          // Turnaround Time
    P.WT  = P.TAT - P.BT         // Waiting Time
    P.RT  = current_time - P.AT  // Response Time
    current_time = P.CT

OUTPUT: CT, TAT, WT, RT for each process
        Average TAT = Σ TAT / n
        Average WT  = Σ WT / n

📝 SJF Pseudocode (Non-Preemptive)

// Shortest Job First (SJF) — Non-Preemptive
INPUT: n processes with {PID, AT, BT}

STEP 1: Initialize current_time = 0, completed = 0
STEP 2: Mark all processes as unfinished

WHILE completed < n:
    // Find all arrived and unfinished processes
    ready_queue = {P | P.AT <= current_time AND P.finished == false}
    
    IF ready_queue is empty:
        current_time++  // CPU idle
        CONTINUE
    
    // Select process with minimum burst time
    selected = process in ready_queue with min(BT)
    
    selected.CT  = current_time + selected.BT
    selected.TAT = selected.CT - selected.AT
    selected.WT  = selected.TAT - selected.BT
    selected.RT  = current_time - selected.AT
    current_time = selected.CT
    selected.finished = true
    completed++

OUTPUT: CT, TAT, WT, RT for each process

📝 Round Robin Pseudocode

// Round Robin Scheduling with Time Quantum q
INPUT: n processes with {PID, AT, BT}, time quantum q

STEP 1: Initialize current_time = 0
         remaining[i] = BT[i] for all processes
         queue = []

STEP 2: Add processes arriving at time 0 to queue

WHILE processes remain:
    IF queue is empty:
        current_time = next_arrival_time
        Add arriving processes to queue
        CONTINUE
    
    P = dequeue first process from queue
    
    exec_time = min(q, remaining[P])
    current_time += exec_time
    remaining[P] -= exec_time
    
    // Add newly arrived processes during this slice
    Add processes that arrived during [old_time, current_time] to queue
    
    IF remaining[P] == 0:
        P.CT = current_time
        P.TAT = P.CT - P.AT
        P.WT  = P.TAT - P.BT
    ELSE:
        Enqueue P at back of queue  // Process not done, re-queue

OUTPUT: CT, TAT, WT for each process

📝 MLFQ Pseudocode

// Multi-Level Feedback Queue (MLFQ)
INPUT: n processes, 3 queues: Q1(RR q=2), Q2(RR q=4), Q3(FCFS)

STEP 1: Place all new processes in Q1 (highest priority)

WHILE processes remain:
    IF Q1 not empty:
        Run front process with quantum q=2
        IF process completes: mark done
        ELSE: move process to Q2
    
    ELSE IF Q2 not empty:
        Run front process with quantum q=4
        IF process completes: mark done
        ELSE: move process to Q3
    
    ELSE IF Q3 not empty:
        Run front process to completion (FCFS)
        Mark done
    
    IF new process arrives:
        Add to Q1 (preempts lower-priority queues)

OUTPUT: CT, TAT, WT, RT for each process

💻 FCFS in C

// FCFS CPU Scheduling Algorithm in C
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    char  pid[10];
    int   at, bt, ct, tat, wt, rt;
} Process;

int cmpArrival(const void *a, const void *b) {
    return ((Process*)a)->at - ((Process*)b)->at;
}

void fcfs(Process p[], int n) {
    qsort(p, n, sizeof(Process), cmpArrival);
    
    int current = 0;
    for (int i = 0; i < n; i++) {
        if (current < p[i].at) current = p[i].at;
        p[i].rt  = current - p[i].at;
        p[i].ct  = current + p[i].bt;
        p[i].tat = p[i].ct - p[i].at;
        p[i].wt  = p[i].tat - p[i].bt;
        current  = p[i].ct;
    }
}

void printResults(Process p[], int n) {
    printf("\n%-6s %-6s %-6s %-6s %-6s %-6s %-6s\n",
           "PID", "AT", "BT", "CT", "TAT", "WT", "RT");
    printf("----------------------------------------------\n");
    
    float sumTAT = 0, sumWT = 0;
    for (int i = 0; i < n; i++) {
        printf("%-6s %-6d %-6d %-6d %-6d %-6d %-6d\n",
               p[i].pid, p[i].at, p[i].bt, p[i].ct,
               p[i].tat, p[i].wt, p[i].rt);
        sumTAT += p[i].tat;
        sumWT  += p[i].wt;
    }
    printf("\nAverage TAT = %.2f\n", sumTAT / n);
    printf("Average WT  = %.2f\n", sumWT  / n);
}

int main() {
    int n;
    printf("Enter number of processes: ");
    scanf("%d", &n);
    
    Process p[n];
    for (int i = 0; i < n; i++) {
        printf("P%d - Arrival Time, Burst Time: ", i+1);
        sprintf(p[i].pid, "P%d", i+1);
        scanf("%d %d", &p[i].at, &p[i].bt);
    }
    
    fcfs(p, n);
    printResults(p, n);
    return 0;
}

💻 Round Robin in C

// Round Robin CPU Scheduling in C
#include <stdio.h>
#include <string.h>

#define MAX 100

void roundRobin(int n, int at[], int bt[], int q) {
    int rem[MAX], ct[MAX], wt[MAX], tat[MAX];
    int queue[MAX*10], head = 0, tail = 0;
    int inQueue[MAX] = {0};
    int done = 0, t = 0;
    
    for (int i = 0; i < n; i++) rem[i] = bt[i];
    
    // Enqueue processes arriving at time 0
    for (int i = 0; i < n; i++)
        if (at[i] == 0) { queue[tail++] = i; inQueue[i] = 1; }
    
    while (done < n) {
        if (head == tail) { t++; continue; } // Idle
        
        int i = queue[head++];
        int exec = (rem[i] < q) ? rem[i] : q;
        int start = t;
        
        t += exec;
        rem[i] -= exec;
        
        // Enqueue newly arrived
        for (int j = 0; j < n; j++)
            if (!inQueue[j] && at[j] <= t && at[j] > start) {
                queue[tail++] = j; inQueue[j] = 1;
            }
        
        if (rem[i] == 0) {
            ct[i] = t;
            tat[i] = ct[i] - at[i];
            wt[i]  = tat[i] - bt[i];
            done++;
        } else {
            queue[tail++] = i; // Re-queue
        }
    }
    
    printf("\n%-4s %-4s %-4s %-4s %-5s %-4s\n",
           "PID", "AT", "BT", "CT", "TAT", "WT");
    
    float avgTAT = 0, avgWT = 0;
    for (int i = 0; i < n; i++) {
        printf("P%-3d %-4d %-4d %-4d %-5d %-4d\n",
               i+1, at[i], bt[i], ct[i], tat[i], wt[i]);
        avgTAT += tat[i]; avgWT += wt[i];
    }
    printf("Avg TAT=%.2f, Avg WT=%.2f\n", avgTAT/n, avgWT/n);
}

int main() {
    int n, q;
    printf("Processes, Quantum: "); scanf("%d %d", &n, &q);
    int at[n], bt[n];
    for (int i=0; i<n; i++) {
        printf("P%d AT BT: ", i+1); scanf("%d %d", &at[i], &bt[i]);
    }
    roundRobin(n, at, bt, q);
    return 0;
}

📊 Observations & Analysis

  • FCFS is simple but suffers from the Convoy Effect — short processes wait for long ones.
  • SJF gives the minimum average waiting time among non-preemptive algorithms.
  • SRTF (preemptive SJF) can lead to starvation of longer processes.
  • Round Robin ensures fairness but has higher average TAT than SJF.
  • Smaller quantum in RR → better response time but more context switches (overhead).
  • MLFQ provides a balanced approach — favors interactive/IO-bound processes.

🚌
Convoy Effect (FCFS): Short processes wait behind one long process. Solution: Use SJF or RR.

❓ Frequently Asked Questions

Common questions about CPU scheduling algorithms, answered clearly for OS lab exams and viva voce.

What is CPU Scheduling and why is it needed? +
CPU Scheduling is the process of deciding which process in the ready queue gets to run on the CPU next. It is needed because multiple processes compete for the CPU simultaneously, and the OS must manage this efficiently to maximize CPU utilization, minimize waiting time, and ensure fairness among processes.
What is the difference between preemptive and non-preemptive scheduling? +
In Non-Preemptive scheduling, once a process gets the CPU, it runs to completion (or until it voluntarily releases). Examples: FCFS, SJF, Priority (NP). In Preemptive scheduling, the CPU can be taken away from a process and given to another. Examples: SRTF, Round Robin, Priority (P). Preemptive scheduling gives better response times but has higher overhead due to context switching.
What is the Convoy Effect in FCFS? +
The Convoy Effect occurs in FCFS when a long CPU-bound process holds the CPU while many short processes wait in the queue. This causes poor CPU utilization and high average waiting time. It's analogous to being stuck behind a slow truck on a single-lane road. The solution is to use algorithms like SJF or Round Robin.
Why is SJF said to be optimal? +
SJF is proven to give the minimum average waiting time among all non-preemptive scheduling algorithms. This is because by running shorter jobs first, we minimize the number of jobs that have to wait behind each job. However, it requires knowing burst times in advance, which is impractical in real systems. Practical implementations use past behavior (exponential averaging) to estimate burst times.
What is starvation and how is it solved? +
Starvation occurs when a process waits indefinitely because higher-priority or shorter processes keep arriving and taking CPU time. This happens in SJF (long processes starve) and Priority Scheduling (low-priority processes starve). The solution is Aging — gradually increasing the priority of waiting processes so they eventually get scheduled.
How do you choose the right time quantum for Round Robin? +
The time quantum (q) should be:
• Not too small: Otherwise, most time is spent on context switching overhead.
• Not too large: Otherwise, it degrades to FCFS behavior.
• Rule of thumb: Set q slightly larger than the typical CPU burst time, so that ~80% of CPU bursts are shorter than q. In practice, modern systems use quantum values of 10–100 milliseconds.
What is MLFQ and how does it work? +
Multi-Level Feedback Queue uses multiple queues with different priority levels. New processes enter the highest-priority queue. If a process uses its full time quantum, it's moved to a lower-priority queue (penalizing CPU-bound processes). If it yields CPU early (I/O-bound), it stays at high priority. This automatically classifies processes by their behavior — I/O-bound processes (interactive) get better response times, while CPU-bound processes gradually move to lower-priority FCFS queues. MLFQ is used in modern OSes like Linux and Windows.
What is Response Time vs Turnaround Time vs Waiting Time? +
• Turnaround Time (TAT): Total time from process arrival to completion. TAT = CT − AT
• Waiting Time (WT): Time spent in the ready queue waiting for CPU. WT = TAT − BT
• Response Time (RT): Time from arrival to first CPU allocation. RT = First CPU time − AT

Response Time is important for interactive systems. Turnaround Time matters for batch systems. Waiting Time is a measure of CPU scheduling efficiency.
What is the difference between throughput and CPU utilization? +
• CPU Utilization: Percentage of time the CPU is busy executing processes (not idle). Formula: (Total busy time / Total elapsed time) × 100%. Goal: Keep this as close to 100% as possible.
• Throughput: Number of processes completed per unit time. Formula: n / Total time. Higher throughput = more work done per unit time.
Can burst time be predicted in real operating systems? +
Burst time cannot be known exactly in advance. Real OSes estimate it using Exponential Averaging:

τ(n+1) = α × t(n) + (1-α) × τ(n)

Where τ(n+1) is the predicted next burst, t(n) is the actual last burst, and α (0 ≤ α ≤ 1) controls how much weight is given to recent vs. old history. α = 0.5 is commonly used. This technique is used in modern MLFQ-based schedulers.
